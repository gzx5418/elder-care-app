摘　要
银龄助手是一款面向老年人的智能服务APP，为社会实践团队自主研发的作品。项目针对老年人面临的数字办事难、电信诈骗高发、健康管理薄弱三大问题，将本地知识库、反诈规则引擎、健康急症检测、语音交互与可选的大模型增强能力整合为一款安装即用的安卓应用。当前版本为 v3.2（Android 独立 APP），采用「APK 本地核心 + 可选联网 AI 增强 + FastAPI 仅调试模式」的三层架构，核心功能完全离线可用。
项目的主要成果包括：一是功能完整，覆盖生活助手、反诈检测、健康指南、备忘录吃药提醒、家属模式与紧急联系五大场景，并新增武汉话、四川话、上海话、粤语四类方言语音识别；二是安全可信，依据 OWASP 规范完成全量安全审查，18 项安全问题全部修复，具备隐私脱敏、图片识别确认、反诈高危不降级、急症优先直返 120 提醒等多重防护；三是质量可证，累计通过 103 项真机功能测试、5 任务适老化可用性测试、36 个 pytest 自动化测试与 30 条反诈测试样例，通过率 100%；四是工程落地，基于 Capacitor 6 实际构建出 4.98 MB 的 Debug APK，安装后无需任何服务器即可运行。
本文档是项目全部资料的整合成果，系统呈现项目背景、技术架构、功能实现、适老化设计、隐私与安全、版本演进、测试证据、构建部署与答辩演示等方方面面，可作为评审、归档与后续迭代的完整依据。
1　项目概述
1.1　项目定位与总体思路
中国正快速进入老龄化社会，老年群体在数字化生活中面临真实而普遍的障碍。银龄助手定位为「专为老年人设计的智能服务APP」，把大模型能力、反诈检测、健康安全与适老化交互结合在一起：老人用一句话即可询问生活办事方法并获得分步骤指引；把可疑短信粘贴进来即可立刻判断是否诈骗并获得应急流程；设置吃药提醒后不漏服药、不忘事项；咨询健康问题时可触发九类急症识别与健康科普。
项目遵循四项关键设计原则：离线优先，核心功能不依赖网络与服务器，APK 安装即用；隐私可控，默认不上传任何数据，AI 增强需用户主动开启并配置密钥；适老化真诚，不是简单放大字体，而是从交互、文案、容错、家属协同多维度设计；可展示可验证，具备完整的演示脚本、测试报告、项目说明书与可用性测试证据。

2　项目背景与社会需求分析
2.1　老龄化背景与三大数字鸿沟
截至 2024 年，我国 60 岁以上人口超过 2.9 亿，占总人口 21% 以上。老年人在数字化生活中主要面临三重鸿沟：其一是数字办事难，交话费、缴水电费、医院挂号、连接 WiFi 等基础操作对年轻人轻而易举，对老人却构成实际门槛；其二是电信诈骗高发，老年人占电信诈骗受害者的 60% 以上，冒充公检法、冒充银行、中奖诈骗等手法屡见不鲜；其三是健康管理薄弱，老人慢性病多发，但缺乏用药提醒、急症识别与健康科普的便捷渠道。
2.2　现有方案的不足
针对上述问题，现有方案均存在明显局限。国家反诈中心APP 以被动预警为主，老人无法主动查询一条可疑短信的真伪，界面也未经适老化设计；子女远程帮助在子女不在身边时无法及时介入，且老人常因羞于承认被骗而错过黄金止损时间；大模型通用助手回答冗长、不分步骤、不做风险拦截，缺乏针对老人的解释方式与安全兜底。银龄助手正是为弥补这些空白而设计。
2.3　需求结论与产品目标
综合背景分析，项目将产品目标收敛为四个一句话场景：一句话问生活办事，分步骤教老人操作；粘贴可疑短信，立即判断是否诈骗并给出应急流程；设置吃药办事提醒，不漏吃药不忘事；咨询健康问题，识别九类急症并坚持科普免责。这四个场景同时也是答辩演示与可用性测试的主线。
3　系统架构与技术实现
3.1　总体架构
v3.2 采用「Android APK 本地核心 + 可选联网 AI 增强 + FastAPI 仅调试模式」的三层架构。最内层是适老化 UI 层，由 8 个页面与统一 SVG 图标系统（80 余个图标）构成；其上是本地核心能力层，包含生活知识库（offline_knowledge.js）、反诈规则引擎（offline_fraud_engine.js）、健康引擎（offline_health_engine.js）、隐私脱敏（offline_privacy.js）、原生桥接（native_bridge.js）与语音输入（voice_input.js）六个模块，全部默认离线可用；再上层是可选的 AI 增强层（ai_client.js），提供 OpenAI 兼容的大模型客户端、配置管理（AIConfig）与调用量管控（AIUsageGuard）。
原生能力由 Capacitor 6 插件提供，包括本地通知（Local Notifications，配合 AlarmManager 在 APP 关闭后仍可弹窗）、分享与短信 Intent、原生 TTS 朗读（声明 25 个以上引擎包名以保证国产机型可用）、语音识别以及日历同步；ML Kit 本地 OCR 接口已预留。当用户开启 AI 增强后，应用按 OpenAI 兼容协议调用用户自持的第三方大模型服务（硅基流动、智谱、通义、OpenAI 均可），文本模型与视觉模型可独立配置。FastAPI 后端仅在「服务器调试模式」下使用，普通用户无需部署。

4　核心功能模块
4.1　生活助手
生活助手支持文字与语音两种输入。默认离线模式下，前端调用 OfflineKnowledge.searchLifeAnswer() 在本地知识库中检索，知识库覆盖话费、水电、挂号、WiFi、字体调整、微信支付、支付宝、乘车码、手电筒、吃药共 10 类场景，并内置 16 组同义词扩展，例如「如何缴纳电力费用」能够命中「电费」条目。命中后返回一句话说明、分步骤卡片与风险提示的结构化结果，每一步可附带风险提醒，并可点击「朗读给我听」由原生 TTS 或 Web Speech API 兜底播报。
开启 AI 增强后，应用先取得本地结构化结果，再将其作为上下文交给大模型润色，AI 失败时自动降级回本地结果。AI 调用受每日 30 次上限与单次 2000 字长度限制约束。
4.2　反诈检测（双引擎）
反诈检测是项目的核心模块，采用「本地规则引擎 + 可选 AI 引擎」的双引擎架构。规则引擎基于关键词评分：21 个高危关键词、6 个链接关键词与敏感操作词，配合组合规则（链接 + 敏感操作强制判高危，评分不低于 70）与官方电话白名单（避免误判银行官方短信）。风险分为三档：低于 30 分为低风险，30 至 59 分为可疑，60 分及以上为高危；同时识别「已转账、已点链接、已给验证码」三类应急动作。
AI 引擎仅在用户开启增强后参与，它以规则引擎的结果为上下文，用老人能看懂的语言解释诈骗手法并给出建议；规则评分不低于 70 时强制保持高危，AI 不可降低等级或评分。不可信输入通过 XML 标签隔离并辅以 system 声明，实现 Prompt 注入防护。
高危结果页提供「我还没操作、我点了链接、我已转账」三个应急入口，每个入口展示分步应急流程并支持朗读，同时直接提供 110、96110 反诈专线与银行客服的拨打按钮。v3.2 新增「生成报警说明」功能，一键生成包含时间、可疑信息、风险检测结论、已采取措施与请求事项的格式化报警文本，支持复制、分享给家人与拨打 110。
图片识别路线统一为联网视觉大模型：上传前先校验视觉模型配置完整性与图片大小（不超过 10MB），经隐私确认弹窗告知「图片将发送到第三方 AI 平台」后，图片压缩至 1280px 并转 base64 调用视觉模型提取文字，再交由本地规则引擎检测，AI 仅作解释。识别失败时友好提示改用文字输入。系统预置硅基 Qwen2-VL-72B、智谱 GLM-4V、通义 Qwen-VL-Plus 与 OpenAI GPT-4o-mini 四个视觉模型预设。
4.3　健康指南与急症识别
健康指南内置 7 类健康知识，覆盖高血压、糖尿病、饮食、运动、防跌倒、睡眠与急救。健康引擎 offline_health_engine.js 持续检测九类危险症状：胸痛胸闷、中风征兆、呼吸困难、严重出血、剧烈头痛、意识不清、严重外伤、过敏反应与高热。一旦命中，应用优先直接返回「立即拨打 120」的急救提醒，不走大模型流程，避免网络延迟贻误救治；所有健康类回答均附免责声明，说明内容仅供参考、不能替代专业医生诊断。
4.4　备忘录与吃药提醒
备忘录支持吃药、喝水、复诊、缴费、生日等提醒类型，数据存于本地并可由语音创建。吃药提醒在通用提醒之上增强：记录药名、剂量、时间与每日重复设置；每条提醒提供「已吃」与「稍后提醒」按钮，同一提醒延迟 2 次以上即变红警告并自动通知家属。
通知能力基于 Capacitor Local Notifications 与 AlarmManager：APP 被系统杀死后 NotificationAlarmReceiver 仍会按时弹出通知；通知 ID 经取模规范化到 32 位 Java int 范围，避免越界失效；Android 13 及以上系统主动请求 POST_NOTIFICATIONS 权限，用户拒绝时页面顶部显示大字红色横幅引导前往设置；提醒还可同步到系统日历「银龄助手提醒」（普通提醒提前 30 分钟、吃药提醒提前 15 分钟提醒，橙色主题）。
4.5　家属模式与紧急联系
家属模式保存家属姓名、电话与通知开关。三个场景会触达家属：反诈检测高危时一键「通知家人」；吃药提醒延迟 2 次以上自动通知；首页紧急联系弹窗中一键求助。v3.2 将通知家人升级为真实调起系统分享或短信 Intent（NativeBridge.sendSms 与 shareText），并按「Capacitor 插件、Web Share API、剪贴板」三级降级，演示版也能真实调起系统应用。首页「快捷操作」区另设紧急联系按钮，弹窗内可一键拨打 120、拨打家属电话或发送求助短信。
4.6　方言语音识别（v3.2 新增）
针对老年用户习惯说方言、普通话不标准的痛点，v3.2 新增方言识别，支持武汉话、四川话、上海话、粤语、普通话与自动识别六种模式，覆盖生活助手、反诈检测与备忘录三大语音入口。方案采用两阶段流水线：第一阶段由 SenseVoice 多语言语音模型将方言语音转写为近音普通话文本；第二阶段由大模型按内置方言特征词典进行近音纠错（temperature 取 0.1），例如武汉话「过早」纠正为「吃早饭」、「岔的」为「可以」、「冇得」为「没有」，四川话「啥子」为「什么」，上海话「侬」为「你」。纠错失败时自动回退 ASR 原文，不影响基础使用；录音开始时以提示语告知当前方言。选择该方案而非专用方言 ASR，是因为其零额外成本（复用现有服务账号）、覆盖面广且常用短语识别率可接受。
4.7　统一 SVG 图标系统
v3.1 起全站启用统一 SVG 图标库（icons.js 与 icons.css），以 80 余个线性图标替代散落的约 150 个 emoji。图标采用 24×24 viewBox、1.6px 描边、currentColor 继承，提供三种样式：icon-circle（48×48 圆角彩色背景，用于分类入口与状态页）、icon-inline（1em 行内，用于标题段落）与 icon-bullet（32×32 圆角方块，用于列表前缀），并可用五种色调类切换语义色。静态 HTML 在页面加载时由 IconLib.mountAll() 自动挂载；动态插入的内容必须在 innerHTML 赋值后显式调用 IconLib.mount(container)，数据文件中的图标名与图标库键名保持严格一致。

6　隐私保护与权限说明
6.1　整体原则
应用遵循五项隐私原则：本地优先，生活助手、反诈规则检测、健康知识、备忘录等核心功能均在本地完成；最小必要，仅申请功能所需的最小权限，不申请通讯录、位置、相机、相册、短信发送等敏感权限；用户可控，所有联网与上传操作均需用户主动开启和确认，可随时关闭或清除；不上传个人数据到自建服务器，应用没有自建后端服务器，除第三方 AI 平台外不向任何服务器发送用户数据；可降级，拒绝任何权限或关闭联网后，应用仍可在离线基础版下正常使用核心功能。

6.3　数据流向说明
数据流向分为三类。第一类是完全本地处理：离线问答与知识检索存于 localStorage，反诈规则检测结果与健康科普不存储，备忘录提醒存于 localStorage 并由 AlarmManager 调度，家属信息存于本地，语音朗读由系统 TTS 引擎本地合成，以上均不上传任何数据。第二类是仅在 AI 增强开启时上传第三方平台：生活与健康问答上传问题文本（最长 2000 字）；反诈解释上传已脱敏的短信文本；图片识别上传压缩后的截图（最长 1280px、10MB，图片无法脱敏，须经用户确认）；语音识别上传录音文件。第三类是调起系统应用：通知家人与分享由用户在系统分享面板中选择目标应用，拨打 120、110、96110 通过 tel: Intent 调起系统拨号器，应用本身不发送短信、不拨打电话。
6.4　API Key 管理与调用限制
API Key 由用户在「应用设置」自行填入，应用不内置任何密钥。演示版将 Key 保存在 localStorage 并已在界面与文档中明示风险；「不保存（临时使用）」模式下 Key 不写入本地存储，退出应用即清除；「一键清除 API Key」按钮可立即删除已保存的 Key 与调用统计；正式版建议改用 Android Keystore 加密保存。为防止误操作消耗额度，应用实施四项调用限制。

6.5　隐私保护措施
反诈检测的脱敏由 OfflinePrivacy.desensitizeText() 在调用大模型之前完成，手机号、身份证号、银行卡号、邮箱与验证码五类个人信息被替换为星号形式（例如 13800138000 变为 1**********00），大模型仅能获得理解上下文所需的最少信息且无法还原原文；应用内部日志仅记录脱敏后的摘要，不记录完整输入或识别文本。急症场景不调用 AI，确保紧急情况下的响应速度与网络无关。图片在识别期间以 base64 形式驻留内存，识别完成或异常后立即释放，不持久化保存，用户亦可自行删除相册中的截图。
6.6　第三方服务说明
应用涉及的第三方服务共有三类：一是硅基流动（可替换为智谱、通义、OpenAI 等 OpenAI 兼容平台），提供文本、视觉与语音识别模型推理，用户输入的文本、图片或音频经其接口返回生成结果，数据处理遵循其隐私政策；二是 Android 系统 TTS 引擎，文本交由系统引擎在本地合成语音，通常不联网；三是 Android 系统日历，提醒通过 CalendarProvider 写入本机日历数据库，是否同步云端由用户的系统账户设置决定，应用不主动上传。
6.7　合规声明
应用不收集、不上传、不分享用户个人身份信息到自建服务器；不包含任何广告、统计或推送 SDK；不申请读取通讯录、短信、位置、相册等敏感权限；第三方 AI 服务的数据处理遵循其隐私政策；健康模块内容仅供参考，不能替代专业医生诊断；反诈检测结果基于本地规则引擎，仅供参考，不能作为法律依据。

8.2　各版本要点
8.2.1　v1.0：静态原型
最早的可用版本为纯前端静态页面，验证五大功能模块的可用性。其局限明显：无后端与大模型导致回答固定，无图片识别，无系统通知，且仅能以 Web 预览、无法打包为手机应用。
8.2.2　v2.x：真实 AI 与工程化
v2.0 接入真实大模型（支持任意 OpenAI 兼容接口），建立「规则引擎 + 大模型」反诈双引擎并确立规则分不低于 70 强制保持高危的原则，同时以百度 OCR 实现截图识别。v2.1.0 解决性能与稳定性问题：以 asyncio 线程池包装同步调用消除阻塞；新增 LRU 缓存使相同问题的响应时间从 2307 毫秒降至 1 毫秒（约 2300 倍提升）；反诈规则配置化并预编译；知识库扩充同义词。v2.2.0 转向安全与工程化：新增隐私脱敏服务与健康安全引擎，强化官方电话白名单、组合规则与 Prompt 注入防护，补齐 36 个 pytest 测试与 30 条 CSV 样例，实现 Docker 化部署、缓存版本化与知识库元数据。
8.2.3　v3.0：离线优先与 Android 独立
v2.x 的根本问题是前端必须依赖后端：部署需要 Python 服务器，老人与家属难以自行部署，答辩需要服务器环境，离线场景完全不可用。v3.0 据此将核心能力整体下沉到前端，实现 APK 安装即用；确立三种运行模式；备忘录与吃药提醒改用 Capacitor 本地通知；图片识别从百度 OCR 迁移到视觉大模型；隐私脱敏同步前端化。OCR 路线随之统一：百度 OCR 仅保留于调试模式，视觉大模型为当前路线，ML Kit 本地 OCR 为后续规划。
8.2.4　v3.1：视觉规范统一与收尾优化
v3.1 建立统一 SVG 图标系统并打通首页语音助手全链路（识别未命中关键词时跳转生活助手页由 AI 正式回答），修复通知 ID 超出 32 位整数范围的缺陷。收尾阶段完成六项优化：文档一致性修订；设置页新增一键清除密钥、临时使用模式与每日调用上限；图片识别前增加隐私确认弹窗；扩充真机可靠性测试与多机型通知测试矩阵；新建适老化可用性测试；产品层新增「我遇到危险了」大按钮、反诈高危结果页「生成报警说明」与家属通知的真实 Intent 调起。
8.2.5　v3.2：安全加固、方言识别与体验优化
v3.2 依据 OWASP 规范完成全量审查并修复全部 18 项安全漏洞（详见第 7 章）；新增四类方言识别（详见第 4.6 节）；完成卡片等高、标题字号、AI 提示统一、自定义图标、CSP 收紧与 WebView 加固等体验优化，并以 4.98 MB 的 APK 构建成果收束。
8.3　关键决策记录
为什么把核心能力下沉到前端：部署门槛是决定性因素，老人与家属无法自行维护 Python 服务器；同时答辩需要无网演示，地铁与农村等无网络场景也要求离线可用；默认不上传数据的架构让隐私成为默认属性而非可选项。
为什么保留 FastAPI 后端：开发期可快速验证大模型调用与规则匹配；v2.x 的 pytest 测试继续在 后端运行；服务器调试模式允许对比本地与远程结果；未来在线规则更新与家属远程管理后台也以后端为基础。
为什么图片识别选择视觉大模型：零原生改动、不增加 APK 体积；视觉模型能理解截图语义，准确率优于传统 OCR；用户只需填写既有 API 配置。ML Kit 本地 OCR 接口已在 native_bridge.js 中预留，待需求验证后接入以实现完全离线识别。
为什么 API Key 暂存 localStorage 又在 v3.2 移除硬编码：演示期需要开箱即用与快速切换配置，因此用户自持密钥并暂存于本地；但硬编码真实密钥在 APK 分发场景下风险不可接受（反编译约一分钟即可提取），故 v3.2 移除出厂密钥、默认关闭 AI，并在设置页提供配置引导、临时使用与一键清除。
为什么方言识别采用 ASR 加 LLM 纠错而非专用方言 ASR：武汉话等方言在商用 ASR 平台需要单独开通并计费；复用既有服务零额外成本；SenseVoice 多语言模型加方言词典纠错对常用短语已够用；若未来需求集中在单一方言，可再接入专用引擎。
8.4　后续路线图
短期（v3.3）计划将 API Key 迁移到 Android Keystore、接入 ML Kit 本地 OCR 实现完全离线图片识别，并扩充医保、社保、出行等生活知识库；中期（v4.0）规划家属远程管理后台、在线反诈规则更新与健康数据接入（血压计、血糖仪同步）；长期设想 AI 主动关怀、政务办事一键办理以及与社区、街道、医院的联动。

11.2　答辩常见问题预案
为什么不用 React 或 Vue：项目聚焦适老化功能本身，原生 HTML/JS 包体小、加载快、对老设备友好，且前端已通过 api.js、app.js 等模块实现工程化。
大模型答错了怎么办：三重兜底保证安全——规则评分不低于 70 时强制保持高危，大模型不能降级；九类急症优先返回 120 提醒、不走大模型；健康内容一律附免责声明。
老人不会用怎么办：大字体大按钮高对比度、全程朗读支持、语音输入三管齐下；可用性测试证明 5 位老人均可独立完成核心任务。
数据安全如何保证：默认离线不上传；AI 模式下先脱敏再调用、日志只记摘要；图片识别需确认且不落地保存；密钥可临时使用并一键清除。
与市面反诈应用的区别：国家反诈中心以被动预警为主，本应用支持老人主动查询可疑信息，提供老人能看懂的解释与分步指引，并针对「已经中招」场景提供应急流程与报警说明，这是市面应用较少覆盖的。

12.1　项目总结
银龄助手不是一个仅用于演示的原型，而是面向真实社会问题、可落地、有温度的解决方案。回顾全程，项目在六个方面形成了扎实沉淀：功能完整性上，五大模块覆盖老人核心场景且离线可用；技术深度上，实现双引擎融合、缓存优化、安全防护、急症识别与调用量管控；工程质量上，103 项真机测试、5 任务可用性测试与 36 个后端测试全部通过；适老化上，从交互、文案、容错、家属协同与紧急救助多维度真诚设计并经真实用户验证；隐私安全上，默认离线、AI 可选、图片识别需确认、密钥可清除，并以 18 项漏洞全修复通过安全审查；可展示性上，说明书、演进记录、测试报告与演示脚本齐备。团队希望这个项目能切实帮助老年人在数字化时代不被落下。
